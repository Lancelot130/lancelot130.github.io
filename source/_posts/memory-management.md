## 一、进程的虚拟地址空间

- ### 一个进程为什么拥有自己的地址空间

如果直接让每个进程去操作真实存在的物理内存（内存条），那么不同进程存放的数据难免会“打架”；当某个进程出bug了，胡乱读写内存时，其它进程也会受到影响；不同进程的数据之间也缺少“私密性”，可能引发数据安全问题。
所以，操作系统会为每个进程安排虚拟地址空间，让各个进程“认为”自己独占了一整个地址空间，而虚拟地址也对应着一个内存条上的真实的物理地址。当进程需要对地址空间中的数据进行访问读写时，MMU（内存管理单元）会通过“页表”（记录着虚拟地址和真实地址的对应关系）查询该进程的虚拟地址对应的真实地址，实现间接访问。

这样做的好处是：

- 1、进程之间相对隔离，安全性高；
- 2、程序不用查询真实内存哪里还有空地址，方便编译器安排数据的存放地址；
- 3、便于相关的进程共享数据：操作系统可以让两个独立的虚拟地址空间指向同一个物理地址；
- 4、虚拟内存可以比物理内存更大，每个进程可以“幻想”自己有更多的内存。（实际上超出物理内存的数据会被操作系统存放到硬盘上，等需要使用时再挪回来）。

- ### 虚拟地址和物理地址的区别

按我的理解，虚拟地址是操作系统为进程构建的“幻想”，它也存在，但不真实，像是对物理地址的一层掩盖。C语言中，指针自己的地址和变量的地址都是虚拟地址。

物理地址真实存在于计算机的内存条上，是真正存储数据的地方。

二者依靠MMU查询页表建立对应关系，且对应关系并不唯一。

- ### 地址空间各个区域分别有什么用

按地址从低到高，地址空间的各个主要区域及其作用：

#### 1、代码段

存储着程序被编译后的**机器指令**，包括所有函数的二进制代码和编译器自动生成的初始化代码和清理代码等等。CPU从代码段里读取指令，逐条执行。只读，通常不可修改，防止程序运行时意外修改自己的指令。

#### 2、数据段

存储已初始化的全局变量和静态变量。可读也可修改，数据段占用的内存区域总大小在程序启动加载后就已经确定，运行期间大小不变。

#### 3、BSS段

存储未初始化或初始化为 0 的全局变量和静态变量。在可执行文件中，BSS段保存的变量并不占实际空间，只记录所需空间的大小。但程序启动时，操作系统会为BSS段分配内存并最终清零，所以运行时它真实占用内存。

#### 4、堆区

存放动态分配地址，供程序运行时动态分配内存。需要使用 malloc 等函数手动申请内存，并用 free 释放，忘记释放可能会引起内存泄漏导致程序崩溃。内存往更高地址处扩展。具体应用在后面的动态内存管理会阐述。

#### 5、共享库映射区

加载“动态链接库”的区域。我的理解就是它可以帮助程序按需求调用C语言标准函数库里的函数。虚拟地址空间中存在这个区域，使得标准函数可以只存储在一处物理地址空间中，而不用每执行一个程序就被复制一次，占用更多物理地址空间。

#### 6、栈区

存放函数调用的相关信息。由操作系统自动管理，不用手动申请和释放。调用函数时，会在栈上为这个函数开辟一块空间“栈帧”供函数使用，栈帧中包含函数的参数，局部变量等信息。内存往更低地址处扩展：每调用一个函数，栈顶就向下移动，给新栈帧腾出空间；函数返回时，栈顶向上移动，回收栈帧。

#### 7、内核空间

存放操作系统内核的代码和数据，负责系统操作（比如驱动硬件设备，管理内存和进程）。位于进程虚拟地址空间的最高处，用户程序不能直接访问，只能通过系统调用间接使用。所有进程的内核空间都对应到同一份物理内核，节省内存。

## 二、变量的作用域与类型

- ### 变量作用域和生命周期

#### **作用域：定义过的变量在程序中可以被访问的范围。**

变量分为“局部变量”和“全局变量”，局部变量指的是定义在函数内部的变量，也可以是函数的参数，只能在离自己最近的大括号“{}”内被访问。
例如

```c
int main(void)
{
    int i = 0;             //i是main函数里的局部变量

    for (i = 0;i < 3;i++)
    {
        int a = 1;         //a是for循环里的局部变量
        printf("%d ",a);
    }

    return 0;
}
```

这段代码的输出结果是

> 1 1 1

但如果是

```c
int main(void)
{
    int i = 0;             //i是main函数里的局部变量

    for (i = 0;i < 3;i++)
    {
        int a = 1;         //a是for循环里的局部变量
        printf("%d ",a);
    }

    printf("%d",++a);

    return 0;
}
```

代码就无法正常运行，因为 a 是在for循环内被定义的，无法在for的大括号外被访问，但 i 可以。如果把++a换成 i ，就会多输出一个 3 。

全局变量就是声明在所有函数之外的变量，可以在任意函数中被访问。如果用 extern 声明，就可以在同一个工程的所有.c文件中被访问。

```c
extern int GLOBAL_A;    //声明外部全局变量
```

另外，**当全局变量和局部变量重名时，局部变量会“覆盖”全局变量。**

#### **生命周期：变量从分配内存空间开始，到该内存空间被回收为止的这段时间。**

对于局部变量，生命周期从 定义该变量的语句执行时 开始，到 执行到对应的右大括号“}”时结束。
例如

```c
int main(void)
{
    int i = 0;          //生命周期开始

    for (i = 0;i < 3;i++)
    {
        printf("%d",i);
    }

    return 0;
}                       //生命周期结束， i 被销毁
```

对于全局变量，生命周期从 进程被创建时（操作系统为进程分配内存时） 开始，直到整个程序结束时被销毁，特点是全局生命周期。

- ### 变量的存储类型

### 总览

| 类型         | 存储地址     | 作用域                   | 生命周期         | 由谁管理         |
| ------------ | ------------ | ------------------------ | ---------------- | ---------------- |
| 局部变量     | 栈区         | 在定义它的函数或代码块中 | 函数执行期间     | 操作系统自动管理 |
| 全局变量     | 数据段/BSS段 | 整个代码文件             | 整个程序运行期间 | 操作系统自动管理 |
| 全局静态变量 | 数据段/BSS段 | 整个代码文件             | 整个程序运行期间 | 操作系统自动管理 |
| 局部静态变量 | 数据段/BSS段 | 在定义它的函数或代码块中 | 整个程序运行期间 | 操作系统自动管理 |
| 动态分配对象 | 堆区         | 跟随指针，可跨函数使用   | 从被分配到被释放 | 手动管理         |

#### 一些注意点

**局部变量：**

```c
int* func() {
    int a = 10;     //a 是局部变量
    return &a;      //不能返回局部变量的地址
}
```

函数返回后，a 所在的栈帧被销毁。&a 这个地址仍然存在，但那块内存已经不属于任何变量了。访问这个指针（悬空指针）后，就是访问已销毁的内存，结果不确定，可能导致程序崩溃或者读到垃圾值。

但返回 a 的值是可以的

```c
int func() {
    int a = 10;     //a 是局部变量
    return a;       //返回值是可以的，因为返回值是复制出来的
}
```

**静态变量：**

**局部静态变量只会初始化一次，这一点和全局（静态）变量一样。**

比如下列代码：

```c
#include <stdio.h>

void func()
{
    int a = 1;          //局部变量，存储于栈区
    static int b = 0;   //局部静态变量，存储于数据段/BSS段
    b++;
    printf("a=%d, b=%d\n", a, b);
}

int main()
{
    func();
    func();

    return 0;
}
```

最终输出结果是

> a=1, b=1
> a=1, b=2

在第二次调用func函数时，声明变量的过程中静态变量 b 没有被重新初始化为 0 ，而是保留了上一次 b++ 得到的 1。

另外，局部静态变量的作用域是函数或代码块中，但生命周期是整个程序运行期间，对此，我的理解是：

**“有的变量死了，但局部静态变量还活着。”**

如下列代码：

```c
void func()
{
    static int a = 0;    // a 是局部静态变量
    a++;
}
```

由于局部静态变量的存储地址是数据段/BSS段，函数返回时销毁的是栈帧，所以在函数被调用完了之后，它还活着，只是看不见摸不着，无法访问。
但如果利用函数返回了指向局部静态变量的指针，就可以通过指针对它进行间接操作，比如赋值。

```c
int* pi()
{
    static int a = 0;    //局部静态变量
    return &a;           //返回它的地址，安全
}

int main()
{
    int *p = pi();       //拿到地址
    *p = 10;             //间接操作它
    printf("%d\n", *p);
}
```

这是普通局部变量做不到的。

## 三、指针与内存访问

- ### 指针保存的是什么，&、\* 的实际作用和数组变量的本质

我在第一份md文件已经阐述过我对指针的理解了，现在把它引用在这：

> _指针变量存放的是某个对象的内存地址。把一个同类型变量的地址赋给指针后，指针的值就是那个变量的地址。不同数据类型的指针，通常都表示同样形式的地址，但它们的类型不同，类型决定了编译器如何解释这个地址，指针加减时走多少字节。若pi是 int \*，pi的值是它指向的int对象的地址；&pi是指针变量pi自身的地址，类型是int \*\*（指针套指针杀了我吧）；\*pi是解引用，表示pi指向的那个int对象，可以赋给其他变量也可以被赋值。_

“&” 的作用是取出某个变量的地址，“\*”的作用是解引用，通过地址访问那个地址上的数据例如：

```c
int *p = &a;
*p = 1;
```

&a 就是取出变量 a 的地址，在这里让指针 p 指向了变量 a 的地址。
下一步，用“\*”解引用指针 p ，让我们可以访问 p 所指向的地址，在这里我把 1 赋值给了变量 a ，但并没有改变 p 所指向的地址。
现在还可以补充的是，**指针变量保存的是虚拟地址。**

至于数组变量的本质，我也在第一份md文件有所阐述，最重要的一点就是：**数组名在大多数情况下会退化成指向数组第一个元素的指针。**

例如

```c
int a[5] = {1, 2, 3, 4, 5};
```

a 的类型是 int[5]，不是 int\*，但在大多数表达式里，a 会自动转换成 &arr[0]，也就是 int\*。在这些表达式中 a 和 &a[0] 的值相同，都是数组首元素的地址。

```c
printf("%p", a);      //首元素地址
printf("%p", &a[0]);  //首元素地址
printf("%p", &a);     //整个数组的地址，值一样但类型不同
```

- ### 指针运算、数组与指针的关系

指针可以做加减运算，但移动的长度取决于指针类型。比如：
pi++ 不是地址加 1 ，而是地址加 sizeof(int)，也就是 4 字节。
如果 pi 是 char*，pi++ 就是地址加 1 。
如果 pi 是 double*，pi++ 就是地址加 8 。

**总结：指针加减 n，实际地址移动 n × sizeof(指针指向的类型)。**

数组和指针是两个不同的概念，只是当指针指向数组中的元素时，会有一些特殊的性质让人容易分不清。我已经提到过数组名在很多表达式中会退化成指向数组第一个元素的指针，因此对于一个名叫 a 的数组，下面几种写法在表达式中实际上是等价的。

| 数组写法 | 指针写法  | 实际含义                 |
| -------- | --------- | ------------------------ |
| a[n]     | \*(a + n) | 数组 a 的第(n + 1)个元素 |
| &a[n]    | a + n     | 第(n + 1)个元素的地址    |

- ### 空指针、野指针、悬空指针、越界访问

#### 空指针：

空指针就是不指向任何有效内存的指针，其值为 NULL 。

```c
int *pi = NULL;
```

空指针不能被解引用，这会导致程序崩溃。但可以让空指针重新指向另一个变量再解引用。

```c
#include <stdio.h>
int main
{
int *pi = NULL;
int a = 10;

pi = &a;
printf("%d",*pi);

return 0;
}
```

输出结果是

> 10

#### 野指针：

野指针就是没有初始化的指针，指向哪里不确定。

```c
int * pi; //存的是垃圾值
```

不能直接解引用野指针。因为它可能指向**合法内存**，虽然编译器不报错，但会写坏那块内存里的数据，也可能指向**非法内存**，导致进程直接崩溃。因此，在指针定义时就初始化是避免程序出错的好习惯。

#### 悬空指针：

悬空指针是指曾经指向有效内存，但那块内存已经被释放或失效的指针。它本身仍保存着一个地址，但那个地址对应的内存已经不再属于该进程。悬空指针的危害和野指针相似，都要避免直接解引用。

```c
int *pi = (int*)malloc(sizeof(int));
free(pi);
*pi = 10;
```

最终 pi 是悬空指针，直接解引用可能会写坏其他变量，也可能导致程序崩溃。

```c
int* func()
{
    int a = 10;
    return &a;   //函数返回后，a 的栈内存已经失效
}
```

由于函数结束时，a 的栈内存已经被销毁，因此 func 最终返回的指针也是悬空指针。

#### 越界访问：

越界访问指的是访问了数组以外的内存。

```c
int a[5];
a[5] = 10;       //越界，合法下标是 0~4
a[-1] = 10;      //越界
```

有可能会把赋值写到别的变量上，导致数据被破坏，也有可能访问到非法内存，导致进程崩溃。

## 四、动态内存管理

- ### malloc、calloc、realloc、free 和 alloca 的基本用法与区别

#### 1、malloc

```c
void* malloc(size_t size);
```

使用 malloc 在堆区申请一块内存，并返回一个通用指针。分配失败则返回 NULL 。

例如

```c
int *pi = (int*)malloc(10 * sizeof(int));
```

表示的是在堆区申请一块 40 字节大小的内存，返回的一个整型指针，将它赋给 pi 。相当于告诉编译器要把这块内存当作整型数组使用。

需要手动释放内存。

#### 2、calloc

```c
void* calloc(size_t num, size_t size);
```

使用 calloc 在堆区为 num 个大小为 size 的元素开辟⼀块内存，并且把内存中的每个元素初始化为0。分配失败则返回 NULL 。

例如

```
int *pi = (int*)calloc(10, sizeof(int));
```

在堆区申请了 10 个 int 类型的字节，就是 40 字节，并且 10 个元素全部初始化为零。

需要手动释放内存。

#### 3、realloc

```c
void* realloc(void *ptr, size_t new_size);
```

使用 realloc 可以调整已分配内存的大小。扩展失败则返回 NULL 。

例如

```c
int *pi = (int*)malloc(5 * sizeof(int));
pi = (int*)realloc(pi, 10 * sizeof(int));
```

原先已经用 malloc申请了一块 20 字节大小的内存来存放 int 数组，又用 realloc 将这块内存的1大小扩大至 40 字节，可以存放 10 个整数。

**注意：**
realloc 的返回值是调整之后的内存起始位置。
由于 realloc 在调整内存空间的是存在两种情况：

> 情况1：原有空间之后有足够够大的空间
> 情况2：原有空间之后没有足够大的空间

当是情况 1 的时候，要扩展内存就直接在原有内存后追加空间，原来空间的数据不发⽣变化。
当是情况 2 的时候，原有空间之后没有大小够多的空间，扩展的方法是：在堆区上另找⼀个合适大小的连续空间来使用。这样函数返回的是⼀个**新的内存地址**。

另外，当使用 realloc 扩充内存时，要注意不能直接将扩充后的内存地址返回给原来的指针名，不然有可能内存泄漏。
所以可以引入一个中间指针，来辅助我们判断扩展后的指针是否指向 NULL ，避免使内存泄漏和让原来保留的数据失效。

例如

```c
#include <stdio.h>
#include <stdlib.h>
int main()
{
	int* ptr = (int*)malloc(100);
	if (ptr != NULL)
	{
		//使用……
	}
	else
	{
		perror("malloc");
		return 1; // 直接退出，避免后续操作
	}

	//扩展容量
	//先将realloc函数的返回值放在p中，不为NULL，再放ptr中
	int* p = NULL;
	p = (int*)realloc(ptr, 1000);
	if (p != NULL)
	{
		ptr = p;
	}

	//使用……

	//释放
	free(ptr);
	ptr = NULL;// 防止悬空指针（良好习惯）

	return 0;
}
```

这段代码使用了 p 作为一个中间指针，如果扩容失败那么原来的地址依然保留，没有发生内存泄漏，有效地保护了程序。

#### 4、free

```c
void free(void *ptr);
```

free 用来释放 malloc 、calloc 、realloc 返回的内存。
释放后让原来的指针指向 NULL ，防止悬空指针导致内存泄漏。

```c
free(pi);
pi = NULL;
```

#### 5、alloca

```c
void* alloca(size_t size);
```

使用 alloca 在栈区申请临时内存，而非堆区。函数返回时内存自动释放，不用手动 free 。
虽然内存分配速度快，但栈空间有限，分配太大会栈溢出。

- ### 重复释放、释放后使用和 realloc 失败时的处理

#### 重复释放

```c
int *pi = (int*)malloc(sizeof(int));
free(pi);
free(pi);        //重复释放
```

重复释放属于未定义行为，可能导致程序崩溃。
释放 NULL 是安全行为，所以在指针所指地址内存释放后应及时让指针指向 NULL 。

```c
int *pi = (int*)malloc(sizeof(int));
free(pi);
pi = NULL;
free(pi);        //安全，free(NULL) 什么都不做。
```

#### 释放后使用

```c
int *p = (int*)malloc(sizeof(int));
*p = 10;
free(p);
*p = 20;         //释放后使用
```

释放后使用就是访问悬空指针，具体危害在前面已经提到。

#### realloc 失败时的处理

一如前文所提到的，在使用 realloc 改变内存大小时用一个中间指针，将返回值记录在里面，如果扩容失效则返回 NULL ，但原来的内存地址仍然保留在原指针中，数据没有丢失，不会引发内存泄漏。

- ### 为什么动态内存必须由程序员明确管理

有些时候，我们需要对一个数组进行跨函数操作，或者让用户来决定内存的大小。一方面，栈内存的生命周期会随着函数体或代码块的结束而结束，而堆内存的生命周期不固定，申请后就可以实现跨函数操作；另一方面，使用动态内存可以更自由灵活地管理内存，比如让用户输入内存大小。
此外，手动管理相比自动管理（如垃圾回收）节省了运行时的额外开销，让程序运行更高效。但这种自由有一定代价：程序员必须自己负责申请和释放，避免内存泄漏，悬空指针等问题。

## 五、数组、字符串与内存布局

- ### C 字符串（字符数组）的长度为什么是实际字符数量+1

C语言并没有一个专门的数据类型来存储字符串，字符串实际上是由以'\0'结尾的字符数组来定义的。所有处理字符数组的函数都以'\0'作为判断字符数姐结束的标志，因此，在存储字符串时，除了实际输入的字符，还必须多存一个'\0'。
C字符串本身不携带长度信息，函数只能从头开始扫描，直到遇到'\0'才知道结束。没有'\0'在字符串末尾，函数会继续往后读，造成越界访问。

- ### C 语言中多维数组在内存中的排列方式

多维数组在内存中的排列方式十分符合一般直觉，它遵循 **行优先** 的排列方式。

例如

```c
#include <stdio.h>

int main()
{
    int arr[2][3] = {
    {1,2,3},
    {4,5,6}
    };
    int *pi = &arr[0][0];        //指向第一行第一列元素

    for (int i = 0; i < 6; i++)
    {
        printf("%d ", pi);
        pi++;
    }

    return 0;
}
```

输出结果是

> 1 2 3 4 5 6

行优先，其实就是指最右边的下标变化最快，对于更高维的数组也是一样的。

## 六、对象大小与对齐

- ### sizeof 的结果与类型、数组、指针的关系

sizeof 是C语言中用来求某个类型或变量所占用的字节数的函数。它返回 size_t 类型，通常用 %zu 打印。

对于基本类型

```c
#include <stdio.h>

int main()
{
    printf("%zu ",sizeof(int));
    printf("%zu ",sizeof(char));
    printf("%zu",sizeof(double));
    return 0;
}
```

输出结果为

> 4 1 8

对数组

```c
#include <stdio.h>

int main()
{
    int arr[10];

    printf("%zu ",sizeof(arr));

    return 0;
}
```

输出结果为

> 40

这里值得注意的是，**在 sizeof 中，数组名不会退化为指针。**

对指针

```c
#include <stdio.h>

int main()
{
    int arr[10];
    int *pi = arr;

    printf("%zu ",sizeof(pi));

    return 0;
}
```

输出结果为

> 8

指针变量里存的是一个地址，sizeof(pi) 得到的是保存这个地址所需的空间，与它指向什么无关。

**陷阱：**

**当数组作为函数参数时，它会退化为指针**

例如

```c
#include <stdio.h>

void func(int arr[])
{
    printf("%zu",sizeof(arr));

}


int main()
{
    int arr[10] = {1};

    func(arr);

    return 0;
}
```

输出结果为

> 8

也就是保存该数组地址所需的空间。

- ### 结构体成员的内存布局、填充和对齐

首先声明，结构体内部成员的内存对齐对于程序执行的提效来说是有必要的，因为**CPU访问内存时，按对齐边界访问效率最高。**

比如一个 4 字节的 int，如果放在地址是 4 的倍数的位置，CPU一次就能读完；如果放在其它地址，可能需要读两次，降低程序运行效率。

所以编译器会自动插入填充字节，让每个成员都落在合适的对齐边界上。

对齐规则：
每个成员相对于结构体起始地址的偏移量，必须是该成员大小的整数倍。
结构体的总大小，必须是其最大成员对齐数的整数倍。

例如

```c
struct { char a; int b; double c; }
```

它的内存布局会是这样的：

> 从初始地址开始，a 占了一个字节，由于下一个成员是 int 类型，a 的后面三个地址会自动插入 3 个填充字节，以此来把 b 放到地址是 4 的倍数的位置。由于下一个成员是 double 类型，所以 b 的后面又会自动填充 4 个填充字节，以此把 c 放到地址是 8 的倍数的位置。

- ### 为什么不能用 sizeof(pointer) 代替指针所指数组的大小

指针只是一个地址，它本身不携带数组的长度信息。sizeof(pointer) 得到的是保存地址所占的空间。况且在表达式中是数组退化为指针，也不是指针进化成数组。

## 七、两个例子

### 1、局部指针

```c
#include <stdio.h>

// 获取一个字符串
char *get_name(void) {
    char name[] = "Lingrui";
    return name;
}

int main(void) {
    char *name = get_name();
    printf("%s\n", name);
    return 0;
}
```

无法正常运行，弹出警告

> warning: function returns address of local variable

意思是函数返回了一个局部变量。

原因：
局部变量的生命周期是所处的函数或者代码块内，显然，name[] 是一个处于 get_name 这个函数内的局部数组，它的那块存放在栈上，当函数执行结束，栈帧被销毁，name[] 就死掉了，返回的指针变成了悬空指针，我无法在 main 函数内再访问该数组。

### 2、内存泄漏

```c
#include <stdlib.h>
#include <string.h>

int main(void) {
    while (1) {
        char *request = malloc(1024);
        if (request == NULL) {
            return 1;
        }

        strcpy(request, "a request");
        /* 模拟处理 request */

    }
}
```

运行后我的内存占用迅速达到 99%，吓晕。

原因：
这段代码会导致内存泄漏，每一轮循环开始时都会初始化一次 request 这个局部指针，而每一轮循环结束它的生命周期也会结束，但循环体中没有用 free(request) 手动释放分配的内存，所以每一轮循环结束后指针就丢失，导致内存泄漏。最终没有堆内存可分配了，malloc 返回 NULL ，进程死掉。
